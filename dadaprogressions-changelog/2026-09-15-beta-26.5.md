# DadaProgressions beta-26.5

Beta 26.5 is primarily a reliability and server-performance update. It builds on the beta 26.4 hardening work rather than adding a new progression system that server owners must reconfigure.

Existing goal files remain compatible with the current beta configuration model.

## Beta 26.5

### Periodic YAML writes moved off the Bukkit tick

Periodic storage now serializes immutable YAML snapshots on the Bukkit thread and performs filesystem writes on one dedicated writer thread.

This removes routine file I/O from the main server tick while keeping Bukkit configuration objects from being mutated concurrently.

The writer also tracks revisions so an older queued snapshot cannot overwrite a newer synchronous save.

### Durability-sensitive operations stay protected

Reward claims, reloads, backups, and plugin shutdown still use a durability barrier before continuing.

New storage settings are available in `config.yml`:

```yaml
storage:
  async-periodic-writes: true
  save-interval-ticks: 600
  writer-flush-timeout-seconds: 10
```

For normal production beta servers, keep asynchronous periodic writes enabled.

## Beta 26.4 hardening included in this update path

Servers upgrading from beta 26.3 or older also receive the beta 26.4 hardening changes.

### Safer reward claims

Reward claims are reserved as `PENDING` before external reward commands run. This prevents an automatic duplicate reward if the server stops after the external command but before final claim persistence.

Administrators can resolve a protected pending claim with:

```text
/dp admin resolveclaim <goalId> <player> <tierPercent> <markclaimed|retry>
```

### Corrected event accounting

- Cancelled and zero final damage no longer produces progress.
- Projectile damage can be attributed to the player shooter.
- Craft progress accounts for recipe result size and shift-click crafting.
- Playtime uses elapsed online time rather than a global repeating minute tick.

### API and validation hardening

- Public API calls from asynchronous plugin tasks are marshalled to the Bukkit primary thread.
- Progress API booleans now indicate whether progress was actually applied.
- Strict startup validation prevents an invalid goal set from silently becoming a partial runtime configuration.
- Invalid reset timezones and cooldown durations are rejected.
- Several counters now guard against numeric overflow.

### Storage and leaderboard improvements

- Player YAML caching is bounded instead of retaining every historical player indefinitely.
- Player and community leaderboard ordering is cached and invalidated when progress changes.
- Community contribution counters use saturating arithmetic.
- Atomic YAML saving keeps backup safety while reducing unnecessary copy work.

### Build and distribution

The build is now portable and reproducible without developer-specific filesystem paths. CI verifies the complete reactor and the final shaded Java 8 distribution jar.

## Recommended update procedure

For an existing production beta server:

1. run `/dp admin backup`;
2. stop the server;
3. keep the previous jar for rollback;
4. install `DadaProgressions-beta-26.5.jar`;
5. start the server and run `/dp admin validate`;
6. test one PLAYER goal, one COMMUNITY goal, a leaderboard, and one reward claim;
7. restart once and verify persistence before considering the update fully accepted.

See [Installation and updates](/docs/dadaprogressions/getting-started/installation) for the full update checklist.
