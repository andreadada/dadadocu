Notifications and Cooldowns

Notifications live in config.yml. Goal-specific overrides can be placed directly inside a goal.

Use notifications carefully. Progress events can fire a lot, especially for block breaking or combat goals.

Events and channels​

Events:

  • progress
  • tier-unlocked
  • goal-completed
  • claim

Channels:

  • chat
  • actionbar
  • title
  • bossbar

Bossbar delivery is compatibility-safe and falls back on older servers.

Event key reference​

Configure an event under notifications.events.<event-name>. The same keys can be placed under a goal's notifications.<event-name> section as overrides.

KeyTypeAccepted values / purpose
enabledBooleanEnables or disables this notification event.
audienceEnum-like stringplayer sends to the actor; broadcast sends to all online players.
messageStringChat, action-bar, and boss-bar text.
titleStringMain title text; falls back to message when omitted.
subtitleStringSubtitle text; empty by default.
every-progressPositive integerProgress event only. Generates an update when progress crosses each multiple.
channels.chatBooleanSends through chat.
channels.actionbarBooleanSends through the action bar.
channels.titleBooleanSends title and subtitle.
channels.bossbarBooleanSends a temporary boss bar.
bossbar.colorBukkit enum nameCommon values: PINK, BLUE, RED, GREEN, YELLOW, PURPLE, WHITE.
bossbar.styleBukkit enum nameCommon values: SOLID, SEGMENTED_6, SEGMENTED_10, SEGMENTED_12, SEGMENTED_20.
bossbar.progressDecimalFixed value from 0.0 to 1.0; when omitted, goal progress is used.
bossbar.secondsPositive integerHow long the boss bar remains visible.
queueSectionOverrides queue behavior for this event.

Global example​

notifications:
  enabled: true
  channels:
    chat: true
    actionbar: false
    title: false
    bossbar: false
  events:
    progress:
      enabled: true
      audience: player
      every-progress: 1
      message: "<gray>%goal_name%: <aqua>%progress_before%</aqua> -> <green>%progress_after%</green>/<white>%target%</white> <dark_gray>(+%amount%)"
      channels:
        chat: true
        actionbar: true
        title: false
        bossbar: false

Per-goal override​

goals:
  community_daily_mining:
    notifications:
      progress:
        every-progress: 50
        channels:
          actionbar: true
          chat: false
      tier-unlocked:
        message: "<gradient:green:aqua>%goal_name%</gradient> reached tier <gold>%tier%%</gold>!"
        channels:
          chat: true
          title: true
          bossbar: true

Anything missing falls back to the global notification config.

Progress spam control​

every-progress controls how often progress messages are sent.

With this:

every-progress: 10

players get a progress message when the value crosses 10, 20, 30, and so on. Completion still gets announced.

Notification queue​

Beta 26.1 and newer maintain independent FIFO queues for chat, action bar, title, and boss bar. Bursts for the same goal are compacted into one update that preserves the first %progress_before%, the latest %progress_after%, and the summed %amount%.

notifications:
  queue:
    enabled: true
    compact-same-goal: true
    initial-delay-ticks: 8
    poll-ticks: 2
    flush-interval-ticks: 20
    max-size-per-recipient: 32
    debounce:
      enabled: true
      idle-ticks: 40
      max-wait-ticks: 400
      large-increment-threshold: 100
    chat-batch:
      enabled: true
      max-entries: 0
      separator: " <dark_gray>|</dark_gray> "
    max-per-flush:
      chat: 3
      actionbar: 1
      title: 1
      bossbar: 1
    channels:
      chat: true
      actionbar: true
      title: true
      bossbar: true

The sliding debounce restarts after every increment. A queue flushes after the configured idle period, maximum wait, or large accumulated increment, whichever applies first. Set max-wait-ticks or large-increment-threshold to 0 to disable that condition.

Queue settings can be overridden globally, for one notification event, or inside one goal. A channel with queueing disabled sends immediately.

Queue key reference​

KeyTypeDefaultPurpose
enabledBooleantrueEnables queued delivery.
compact-same-goalBooleantrueMerges repeated updates for the same goal/event stream.
initial-delay-ticksInteger ≥ 08Wait before the first queued delivery.
poll-ticksInteger ≥ 12How often the shared queue scheduler checks ready entries. Global setting only.
flush-interval-ticksInteger ≥ 1Channel-dependentMinimum delay between sends for one recipient/channel.
max-size-per-recipientInteger ≥ 132Maximum pending entries for each recipient and channel.
debounce.enabledBooleantrueRestarts the idle timer after new activity.
debounce.idle-ticksInteger ≥ 140Sends after this many quiet ticks.
debounce.max-wait-ticksInteger ≥ 0400Forces a send during continuous activity; 0 disables it.
debounce.large-increment-thresholdInteger ≥ 0100Flushes a compacted goal after this gain; 0 disables it.
chat-batch.enabledBooleantrueJoins ready chat entries into one message.
chat-batch.max-entriesInteger ≥ 00Maximum entries per batch; 0 means all pending entries.
chat-batch.separatorStringStyled pipeText inserted between batched goal summaries.
max-per-flush.<channel>Integer ≥ 1VariesMaximum sends for chat, actionbar, title, or bossbar in one flush.
channels.<channel>BooleantrueDisables queueing for one channel while leaving immediate delivery available.

Minecraft normally runs at 20 ticks per second. For example, 40 ticks is roughly two seconds when the server is not lagging.

Chat batching​

When chat-batch.enabled is true, ready updates for several goals are joined into one chat message while preserving FIFO order:

Daily Builder: 35 -> 45/128 (+10) | Community Weekly Build: 40 -> 50/5000 (+10)

chat-batch.max-entries: 0 includes the complete pending queue. A batch counts as one chat send for the current flush.

Cooldowns​

Cooldowns limit how often progress can be accepted from matching events.

goals:
  player_lifetime_regular:
    period: PERMANENT
    type: LOGIN
    cooldown:
      enabled: true
      scope: PLAYER
      mode: DAILY
      progress-per-acquire: 1
      duration: 24h
KeyTypeDefaultAccepted values / purpose
enabledBooleantrueEnables the cooldown.
scopeEnumPLAYERPLAYER tracks each actor separately. SHARED uses one cooldown for a community goal.
modeEnumDURATIONDURATION, DAILY, WEEKLY, or MONTHLY.
durationDuration string24hUsed by DURATION, for example 500ms, 30s, 30m, 12h, or 7d.
progress-per-acquirePositive integer1Maximum progress accepted when the cooldown opens. amount is a legacy alias.

Calendar modes use the goal timezone. duration is ignored by DAILY, WEEKLY, and MONTHLY.

Shared community cooldown​

goals:
  community_daily_mining:
    scope: COMMUNITY
    cooldown:
      enabled: true
      scope: SHARED
      mode: DAILY
      progress-per-acquire: 25

With scope: SHARED, the first valid contribution starts the cooldown for everyone. Player goals always behave as per-player cooldowns.

On a composite goal, a top-level cooldown is inherited by all event leaves. A leaf-level cooldown section replaces it for that leaf.
