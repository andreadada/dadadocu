Basic goals and keys

File structure​

The recommended format uses a top-level goals: section:

goals:
  player_daily_hunter:
    enabled: true
    scope: PLAYER
    period: DAILY
    type: MOB_KILL
    target: 30

Goal IDs may also be placed directly at the root of a file, but do not mix both formats in the same file.

Goal IDs​

The key below goals: is the goal ID. It is used by commands, placeholders, prerequisites, progress storage, and claims.

  • Length: 1 to 64 characters.
  • Allowed: A-Z, a-z, 0-9, _, and -.
  • IDs are compared case-insensitively and must be unique across every goal file.
  • Keep an ID stable after players begin earning progress. Renaming it creates a different storage identity.

Good IDs are descriptive and include scope or period where useful: player_daily_hunter, community_weekly_builder.

Top-level key reference​

KeyTypeDefaultAccepted values / purpose
enabledBooleantruetrue loads and tracks the goal; false keeps it configured but inactive.
scopeEnumCOMMUNITYPLAYER for separate progress per player; COMMUNITY for one shared total.
periodEnumDAILYDAILY, WEEKLY, MONTHLY, or PERMANENT.
typeEnumCUSTOMEvent source for a simple goal. See Goal types.
targetPositive integer1Progress required by a simple goal. Must be greater than zero.
criteriaSectionNoneReplaces type and target with a composite tree. See Composite goals.
filter-modeEnumALLALL requires every configured filter; ANY requires at least one.
filtersSectionNoneConditions applied to the simple goal or to every leaf of a composite goal.
pointsSectionEvent amountChanges how much progress one matching event awards. On composite goals, configure it on event leaves.
cooldownSectionNoneLimits how often progress can be accepted. progress-cooldown is a legacy alias.
prerequisitesSectionNoneLocks the goal behind other goals or claimed tiers.
claim-modeEnumMANUALMANUAL or AUTO.
displaySectionID and CHESTGUI name, material, and lore.
tiersSectionEmptyClaimable reward milestones keyed by percentage.
reward-commandsString listEmptyLegacy completion commands; used as a 100% tier when tiers is absent.
completion-broadcastStringNoneMessage broadcast the first time the goal completes in its current owner/period context.
reset-settings.timezoneStringGlobal timezonePer-goal IANA timezone such as UTC or Europe/Rome.
notificationsSectionGlobal settingsOverrides notification events or queue settings for this goal.

rewardCommands is accepted as a legacy alias for reward-commands, but the kebab-case key is preferred.

Scope​

PLAYER​

Each player owns separate progress and claims. A player must be known when progress is added.

scope: PLAYER

COMMUNITY​

The server shares one progress value. Individual contributions are still recorded for leaderboards.

scope: COMMUNITY

Period​

ValueMeaning
DAILYUses a date-based daily period key in the configured timezone.
WEEKLYUses an ISO week-based period key.
MONTHLYUses a year/month period key.
PERMANENTDoes not move to a new automatic period.

The default timezone comes from settings.timezone in config.yml. Use reset-settings.timezone only when this goal must reset in a different timezone.

Complete simple example​

goals:
  player_daily_hunter:
    enabled: true
    scope: PLAYER
    period: DAILY
    type: MOB_KILL
    target: 30

    filters:
      entity-type:
        include: [ZOMBIE, SKELETON]
      world:
        include: [survival]

    display:
      name: "<green>Daily Hunter"
      material: "IRON_SWORD"
      lore:
        - "<gray>Defeat 30 zombies or skeletons today."
        - "<gray>Progress: <white>%player_progress%</white>/<white>%target%</white>"

    tiers:
      50:
        name: "<yellow>Halfway"
        reward-commands:
          - "say %player% reached 50% of %goal_name%!"
      100:
        name: "<gold>Hunter Reward"
        reward-commands:
          - "say %player% completed %goal_name%!"

Boolean, number, string, and list values​

  • Boolean: true or false, without quotes.
  • Integer: 30, not "30" unless the documentation explicitly describes the key as a string.
  • Decimal: 1.5, used by point multipliers and criterion weights.
  • String: quote text containing formatting tags, colons, #, or other YAML punctuation.
  • List: use - value lines or [value1, value2].

YAML indentation uses spaces. Tabs are not valid indentation.
